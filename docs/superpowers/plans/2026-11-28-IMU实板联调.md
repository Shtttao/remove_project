# STM32H563 与 ICM-42688-P 实板联调计划

以已完成的硬件检查为起点。第一轮交付一份可复查的下载日志、一段能解码的 60 秒实板数据。最后在机器人实际接收端验收方向、时序、精度和故障恢复。

## 1. 用 X Pulse 主板 Type-C 下载固件

- [ ] **识别单板。** 拔掉台式电源和外设，仅用 USB 数据线连接电脑与主板。X Pulse v1.0 图中 KEY1 拉高 BOOT，KEY2 复位。在板子允许 BOOT 引脚选择系统引导程序的前提下，按住 KEY，按下再松开 RST，最后松开 KEY。在 STM32CubeProgrammer 选择 USB，刷新并连接。通过标志是能读到与 H563 对应的器件信息。只亮电源灯时先查线缆、启动模式和电脑的 DFU 设备识别。
- [ ] **确认写入位置。** 现有工程按 TrustZone 关闭、应用从片内 Flash 的 `0x08000000` 独立启动构建。若起始位置有需要保留的程序，先保存可恢复的原镜像；若商家教程指定保留引导程序或使用另一地址，先核对应用布局。出现读保护、解锁或整片擦除提示时，停在读取信息这一步，保留屏幕提示。
- [ ] **写入与校验。** 在编程页选择工程的 `build/firmware/robot-imu.elf`，它带有加载地址。若教程使用 BIN，则选同目录的 `robot-imu.bin`，显式填 `0x08000000`。两种格式选一份。启用写后校验，保存成功日志；松开 KEY，单按 RST 从应用启动。ICM 模块由 H563 上电后通过 SPI 配置。
- [ ] **证明应用运行。** 单板运行时，PC0 状态灯约每秒闪 4 次。可用示波器观察 PA4 的片选低脉冲和 PB3 的时钟，通常约每半秒可看到新一组连接尝试。仪器地线接板上 GND。此时串口尚无姿态帧。

## 2. 接入传感器，先验证身份再看姿态

- [ ] **核对 SPI 引脚。** 本版固件走 X Pulse 的外部 SPI1 引脚 PB3、PB4、PB5，避开板载外部 Flash U3。若沿用了 PA5、PA6、PA7 的接线，断电后按下表换线。
- [ ] **断电接线。** 按两块板实物丝印认脚。下表依据当前固件与模块 H1 排针；模块的 5 V 输入经板载稳压器降为 3.3 V，SPI 使用 3.3 V 电平。

| X Pulse 主板 | ICM 模块 H1 | 用途 |
|---|---|---|
| 5V | 8 · 5V | 模块供电 |
| GND | 7 · GND | 共地 |
| PB3 | 6 · SCK | 时钟 |
| PB5 | 5 · MOSI | 主板发往传感器 |
| PB4 | 4 · MISO | 传感器回给主板 |
| PA4 | 3 · CS | 低电平选中 |

当前固件按轮询工作，H1 的 1、2 脚 INT2、INT1 可悬空。若要同时抓串口，把 PA2 接到 3.3 V USB 转串口的 RX，两端接 GND，适配器电源脚留空。主板 P1 上标的 TX 连 PA9，当前固件的遥测从 PA2 引出。

- [ ] **读到真实芯片。** 上电后保持桌面静止。PC0 状态灯常亮表示等待静止校准，约每秒慢闪一次表示校准完成。用支持 SPI 解码的示波器或逻辑分析仪，按模式 0、约 1 MHz 抓一次事务。CS 拉低期间，MOSI 第一字节为 `0xF5`，MISO 在第二个字节返回 `0x47`。若有 SWD 探针，也可查看 `imu_app.online` 和持续增长的 `imu_app.samples`。若只有普通示波器，先看 CS/SCK 活动，再用下一步的有效串口帧验证整条链路。波形有时钟但始终读到 `0xFF` 或 `0x00`，先查供电、片选、MISO 和共地。

## 3. 采集 60 秒真实数据

- [ ] 复位后先静置约 2 秒，给固件收集至少 200 个连续静止样本、跨越至少 950 ms。电脑打开 USB 转串口对应的端口，配置 115200、8N1、无流控。用支持**保存原始二进制字节**的串口软件记录 60 秒，文件命名为 `capture.bin`。它和程序镜像 `robot-imu.bin` 用途不同。
- [ ] 在含 Makefile 的工程目录运行下列命令。Windows 上使用 Python 启动器时可将 `python3` 换为 `py -3`。

```text
python3 tools/decode_capture.py capture.bin > capture.jsonl
```

- [ ] 稳态段能连续解出 A1（航向、倾角、更新率）、A2（三轴加速度、去偏角速度与零偏计数）、A3（四元数）。以稳态完整帧 `bad=0`、三类各约 33 帧/秒、A1 的 `update_hz` 接近 200 Hz 为首轮目标。记录各类型实际帧数和抓包时长；分清姿态更新频率与每类串口发送频率。记录首尾截断情况。

## 4. 验证物理方向，再接机器人

| 实验 | 记录与验收 |
|---|---|
| 六面静置 | 让芯片 X、Y、Z 各自朝上和朝下，分别记录 A2 三轴均值。受重力轴应约为 +16384 或 −16384 计数，其余轴接近零。标注轴向和正负号。 |
| 已知转角与静置漂移 | 用直角基准绕已标记轴转 90°，比较相对角变化、方向和回位误差。静置记录航向变化，以 °/min 报告。六轴融合给出相对航向，漂移容限与导师按机器人用途确定。 |
| 复位与恢复 | 做三次冷启动，记录从上电到首帧的时间。台架需要模拟采样中断时，保持两板正常供电，用可控的通信开关或测试夹具中断信号再恢复。检查中断后停止发送旧姿态、恢复并静置后重新出帧。 |
| 机器人验收 | 先让执行器停用，核对安装方向，固定芯片轴到机器人前、侧、上方的映射。接实际接收端，做同一组转动；核对 A1 航向符号、台架版本字以及 A2/A3 解析。若有旧 F103/ICM20689 模块，用同一夹具、同一动作比较新旧输出。最后按机器人实际运行时长复测更新率、误差、漂移及掉线恢复。 |

保留固件版本、下载日志、接线照片、原始抓包、解码结果和测试记录。精度及漂移的合格数值由机器人的需求决定，和导师确认后再作最终判定。
